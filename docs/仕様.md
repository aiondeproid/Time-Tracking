## 1. 目的

紙ベースで運用している勤怠管理を、Web アプリ（Supabase + Next.js）に置き換える。
出勤・退勤の時刻を記録し、任意の期間を指定して Excel ファイルとしてダウンロードできるようにする。

## 2. 利用者と権限

- 想定利用者: 複数人（同一組織内）。
- 勤怠の入力・閲覧・書き出しは **ログイン不要**。利用者はトップで自分の名前を選択して操作する。
- 承認フロー、役割（管理者 / 一般）による機能差は設けない。
- 「名前リストの管理」機能のみ、**ユーザー登録＋ログイン**（Supabase Auth / メール + パスワード）で
  保護する。ログインできれば全操作が可能（ログイン済みユーザー間の権限差は設けない）。
  新規登録には招待コード（`SIGNUP_CODE`）を要求する。
- アプリ全体を、サイト共通の合言葉ゲートで保護する（社内限定運用を想定）。

## 3. 機能一覧

1. 勤怠入力（出勤・退勤の記録）
2. 勤怠一覧（期間・名前で絞り込み表示、行の編集・削除）
3. Excel 書き出し（期間指定、書式付き .xlsx）
4. 名前の管理（手動 CRUD + 並び替え + アーカイブ、Excel/CSV 一括取り込み、テンプレート配布）
5. サイト共通合言葉ゲート

## 4. 画面仕様

### 4.1 勤怠入力

- 上部で名前を選択（アクティブなメンバーのみ）。
- 選択中メンバーの「退勤待ち」の行と、当日分の記録を表示する。
- **[出勤]** ボタン: 現在時刻をプリフィルした入力（勤務日・時刻）を表示。確認 / 修正して保存すると、退勤時刻が空の行が 1 件作成される。
- 退勤待ちの行の **[退勤]** ボタン: 現在時刻をプリフィルした入力を表示。保存するとその行の退勤時刻が確定する。
- 時刻は 1 分単位。丸めは行わない（入力値をそのまま保存）。
- 1 日に複数回の出退勤を登録できる（[出勤] を再度実行すれば新しい行が増える）。
- 各行は後から編集・削除できる（誰でも可、承認不要）。
- 深夜（勤務日境界 4:00 より前）に [出勤] した場合、勤務日は自動的に前日になる（手修正可）。詳細は「5. 勤務日の定義」。

### 4.2 勤怠一覧

- 絞り込み: 期間（勤務日 from〜to、初期値は当月）、名前（任意）。
- 列: 日付（勤務日） / 曜日 / 名前 / 出勤 / 退勤 / 実働時間 / 備考 / 操作（編集・削除）。
- 並び順: 勤務日 → メンバーの表示順 → 出勤時刻。
- 退勤待ちの行は退勤・実働時間を「--:--」で表示。
- 時刻表示は「6. 時刻の表示ルール」に従う。

### 4.3 Excel 書き出し

- 勤怠一覧と同じ絞り込み条件（期間・名前）で [Excel ダウンロード] を実行。
- サーバー側（Route Handler）で `exceljs` により **書式付き .xlsx** を生成。
- レイアウト: 全員を 1 シートにまとめ、勤務日順の一覧。
- 列: 日付 / 曜日 / 名前 / 出勤 / 退勤 / 実働時間 / 備考。
- 書式: 見出し行は太字・背景色・罫線、全セルに罫線、列幅を内容に合わせる、見出し行を固定、最下部に実働時間の合計行。
- 深夜の時刻は 24 時間超え表記（例: 28:00）。
- ファイル名例: `勤怠_2026-09-01_2026-09-30.xlsx`。

### 4.4 名前の管理

ログイン後に利用できる（未ログインは `/login` へ誘導。アカウント作成は `/signup`、招待コード必須）。

- 手動操作: 追加 / 名前の編集 / 表示順の並び替え / アーカイブ（非表示化）。
- **ファイル取り込み**:
  - 対応形式: `.xlsx`、`.csv`。
  - CSV の文字コードは自動判定（UTF-8 / Shift_JIS の両方に対応。Excel が出力する Shift_JIS の CSV をそのまま取り込める）。
  - 列: 「名前」「表示順」の 2 列。ヘッダー行から列名を認識する。認識できるヘッダーが無い場合は 1 列目 = 名前、2 列目 = 表示順として扱う。
  - マージ方式: 名前をキーに **追加 + 更新**。既存の名前は表示順を更新する。ファイルに含まれない名前は変更しない（削除・非表示にしない）。ファイル内の名前が既存のアーカイブ済みメンバーと一致した場合は再アクティブ化する。
  - エラー行（名前が空 / ファイル内で重複 / 表示順が数値でない）はスキップし、正常な行のみ取り込む。スキップした行と理由を一覧表示する。
  - 取り込み前にプレビュー（追加 n 件 / 更新 m 件 / スキップ k 件）を表示し、確定操作で反映する。
  - テンプレート（.xlsx / .csv）をダウンロードできる。
- メンバーの「削除」は物理削除せず、アーカイブ（`active = false`）とする。過去の勤怠データは保持され、勤怠一覧・Excel には引き続き表示される。アーカイブ済みメンバーは勤怠入力の名前選択には表示されない。

## 5. 勤務日の定義（夜勤対応）

- 各勤怠行には「勤務日（work_date）」を持たせる。日付列・期間絞り込み・Excel の集計はすべて勤務日を基準とする。
- 勤務日は **出勤時刻から自動決定** する。境界時刻は **4:00（コードに固定、設定変更機能なし）**。
  - 出勤時刻の（日本時間での）時刻が **4:00 以降** … 勤務日 = その暦日
  - 出勤時刻が **3:59 以前**（深夜）… 勤務日 = その暦日の前日
- 勤務日は出勤時刻で確定する。退勤時刻は勤務日を変更しない。
- 自動決定した勤務日は入力画面で手修正できる。
- 例:
  - 9/3 22:00 出勤 〜 9/4 06:00 退勤 → 勤務日 9/3
  - 9/4 01:30 出勤 〜 9/4 09:00 退勤 → 勤務日 9/3
  - 9/4 03:30 出勤 → 勤務日 9/3
  - 9/4 04:30 出勤 → 勤務日 9/4

## 6. 時刻の表示ルール（24 時間超え表記）

- 行内の時刻（出勤・退勤）は、その行の勤務日 0:00 を起点とした経過時間として `HH:MM` 表示する。翌日にまたぐ時刻は 24:00 以上で表示される。
  - 例: 勤務日 9/3、出勤 22:00・退勤（実際は 9/4 04:00）→ 「22:00 〜 28:00」
- 実働時間 = 退勤日時 − 出勤日時。`HH:MM` 表示（例: 6:00）。合計は 24 時間を超えてもそのまま `HHH:MM` で表示する。
- 退勤時刻が未入力の行は「退勤待ち」。退勤・実働時間は「--:--」。

## 7. データモデル（Supabase / PostgreSQL）

### members

| 列 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| name | text | NOT NULL, UNIQUE | 表示名。取り込みの照合キー |
| sort_order | integer | NOT NULL, default 0 | 表示順（昇順） |
| active | boolean | NOT NULL, default true | false = アーカイブ（非表示） |
| created_at | timestamptz | NOT NULL, default now() | |
| updated_at | timestamptz | NOT NULL, default now() | |

### attendance

| 列 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | uuid | PK, default gen_random_uuid() | |
| member_id | uuid | NOT NULL, FK → members(id) ON DELETE RESTRICT | |
| work_date | date | NOT NULL | 勤務日（出勤時刻 + 4:00 境界から決定、手修正可） |
| clock_in_at | timestamptz | NOT NULL | 出勤日時 |
| clock_out_at | timestamptz | NULL | 退勤日時。NULL = 退勤待ち |
| note | text | NULL | 備考 |
| created_at | timestamptz | NOT NULL, default now() | |
| updated_at | timestamptz | NOT NULL, default now() | |

- インデックス: `attendance(work_date)`、`attendance(member_id, work_date)`。
- 実働時間は DB に保存せず、`clock_out_at - clock_in_at` を都度計算する。
- 時刻はアプリ側で常に日本時間（Asia/Tokyo）に固定して扱う。

## 8. 認証・セキュリティ

- **サイト共通合言葉ゲート**: Next.js proxy（旧 middleware / Node ランタイム）で署名付き Cookie を検証。未認証は合言葉入力ページへ誘導。合言葉は環境変数 `SITE_PASSCODE` と照合。Cookie は httpOnly、有効期限は一定期間（例: 30 日）。
- **「名前の管理」のログイン**: サイト共通合言葉ゲートの内側で、`/members` は Supabase Auth（メール + パスワード）のログイン必須。`proxy` で `getUser()` を検証し、未ログインは `/login` へ誘導。全変更操作（手動 CRUD、並び替え、アーカイブ、ファイル取り込み）の Server Action / Route Handler でも都度ログインを検証する（多層防御）。ログイン済みユーザー間の権限差は設けない。DB 書き込みは従来どおり `SUPABASE_SERVICE_ROLE_KEY` を使用。
  - **セッション**: `@supabase/ssr` の Cookie セッション。`proxy` は `/members`・`/login`・`/signup` のときだけアクセストークンをリフレッシュする（他パスは高速パスのまま）。
  - **ユーザー登録**: `/signup` で作成。招待コード `SIGNUP_CODE`（サーバー環境変数、定数時間比較）が一致した場合のみ、サーバーが `service_role` の `admin.createUser`（`email_confirm: true`）でユーザーを作成し、そのままログインさせる。Supabase 側の公開サインアップは無効でよい。確認メール・SMTP は不要。
- **RLS ポリシー**:
  - `attendance`: anon ロールに SELECT / INSERT / UPDATE / DELETE を許可（ログイン不要のため）。外周はサイト共通合言葉ゲートで担保する。
  - `members`: anon ロールに SELECT のみ許可。INSERT / UPDATE / DELETE は許可しない（サーバー経由・サービスロールでのみ変更）。
  - `auth` スキーマは Supabase 管理。マイグレーションの追加は不要。
- `SUPABASE_SERVICE_ROLE_KEY` はサーバー環境変数のみ。クライアントに露出させない（`NEXT_PUBLIC_` を付けない）。

## 9. 技術構成

- Next.js（App Router）/ TypeScript
- Tailwind CSS
- `@supabase/supabase-js` v2（ブラウザ用クライアント + サーバー用サービスロールクライアント）
- `@supabase/ssr`（「名前の管理」のログイン。Cookie セッションの読み書き）
- `exceljs`（.xlsx 生成・テンプレート生成）
- CSV: `papaparse`（パース）+ 文字コード判定・変換（Shift_JIS 対応。`encoding-japanese` 等）
- `zod`（入力バリデーション）
- `dayjs` + `utc` / `timezone` プラグイン + `locale/ja`（曜日・タイムゾーン処理）
- 取り込み・書き出しの処理は Route Handler（Node ランタイム）で実行。

## 13. 実装ステップ

0. 本仕様書（`docs/仕様.md`）をコミット
1. `create-next-app`（TypeScript / App Router / Tailwind / ESLint）で既存リポジトリにセットアップ
2. Supabase プロジェクト作成、キー取得。`members` / `attendance` テーブルと RLS ポリシーのマイグレーション作成・適用
3. Supabase クライアント（ブラウザ用 / サーバー用サービスロール）と、日本時間・勤務日・時刻表示のユーティリティ（単体テスト付き）

5. 勤怠入力画面（名前選択、[出勤] / [退勤]、退勤待ち一覧、行の編集・削除、勤務日自動判定）
6. 勤怠一覧画面（期間・名前の絞り込み、24 時間超え表記、編集・削除）
7. Excel 書き出し（Route Handler + ダウンロードボタン）
8. 名前の管理（手動 CRUD + 並び替え + アーカイブ、ファイル取り込みのプレビュー → 確定、テンプレート配布）
9. 仕上げ（空状態・バリデーションメッセージ・スマホ表示）
10. デプロイ設定（Vercel 環境変数、Supabase マイグレーション適用手順、README）
11. 「名前の管理」の保護をユーザー登録＋ログイン（Supabase Auth / 招待コード制）へ変更（2026-09-09、改訂履歴参照）
